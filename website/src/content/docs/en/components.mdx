QuickGUI ships low-level primitives and accessible compound component families. They are unstyled: the core supplies behavior and semantics while your app supplies every visible surface.

## Primitives

Use [View](/docs/components/view), [Text](/docs/components/text), [Button](/docs/components/button), [Input](/docs/components/input), [TextArea](/docs/components/text-area), [Markdown](/docs/components/markdown), [Image](/docs/components/image), [Svg](/docs/components/svg), [Shader](/docs/components/shader), [VirtualList](/docs/components/virtual-list), and [Terminal](/docs/components/terminal) as the retained building blocks.

## Compound components

A compound family exposes named parts. The root coordinates state and the Rust core owns keyboard behavior, focus, accessibility relationships, mount policy, and exact interaction deadlines.

```tsx
<Tabs.Root value={tab()} onValueChange={setTab}>
  <Tabs.List>
    <Tabs.Tab value="general"><Text>General</Text></Tabs.Tab>
    <Tabs.Tab value="advanced"><Text>Advanced</Text></Tabs.Tab>
    <Tabs.Indicator />
  </Tabs.List>
  <Tabs.Panel value="general"><GeneralSettings /></Tabs.Panel>
  <Tabs.Panel value="advanced"><AdvancedSettings /></Tabs.Panel>
</Tabs.Root>
```

## Controlled state

Most roots accept a controlled value and matching callback, plus a `default*` value for uncontrolled use.

```tsx
const [open, setOpen] = createSignal(false);

<Dialog.Root open={open()} onOpenChange={setOpen}>
  {/* parts */}
</Dialog.Root>
```

The callback reports the result accepted by the core. Update the signal to keep a controlled declaration in sync.

## Component families

| Area | Components |
| --- | --- |
| Forms | Checkbox, Radio, Switch, Select, Combobox, NumberField, DateField, OtpField |
| Layout and data | Tabs, Accordion, Splitter, ScrollArea, Table, Tree |
| Feedback and overlays | Progress, Meter, Toast, Tooltip, Popover, Dialog, Drawer |
| Menus and navigation | Menu, PopoverMenu, ContextMenu, Menubar, NavigationMenu, Router |

Every public family has its own page in the sidebar, including its parts, key props, and a working composition.

## Styling parts

Style each visible part with `style`. Component state is projected onto retained nodes, so hover, focus, selection, and accessibility behavior do not depend on a web runtime.

```tsx
<Switch.Root
  checked={enabled()}
  onCheckedChange={setEnabled}
  style={{ width: 38, height: 22, borderRadius: 11 }}
>
  <Switch.Thumb style={{ width: 18, height: 18, borderRadius: 9 }} />
</Switch.Root>
```
