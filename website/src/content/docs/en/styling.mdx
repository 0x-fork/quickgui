Primitives accept style options and children directly. Compound parts accept a `ui.Style` through `ui.PartProps`.

## The style prop

Use functional options for short declarations. Reuse a record with `ui.WithStyle(style)`. Numeric lengths are logical pixels; strings also accept percentages. A numeric zero is meaningful; `nil` omits the value. Run `bun run fmt` to wrap long component calls consistently.

```go
func Card() {
	ui.View(
		ui.Padding(20),
		ui.BorderRadius(12),
		ui.BackgroundColor("#111827"),
		ui.Text(ui.Color("#e2e8f0"), "Hello"),
	)
}
```

## Flexbox

Set `Display("flex")`, choose a direction, then declare sizing and alignment. A scrolling flex child usually needs `MinHeight(0)` or `MinWidth(0)` so it can shrink.

```go
func Row() {
	ui.View(
		ui.Display("flex"),
		ui.Gap(12),
		ui.AlignItems("center"),
		func() {
			ui.Text(ui.Flex(1), ui.MinWidth(0), "Flexible content")
			ui.Button(ui.FlexShrink(0), "Action")
		},
	)
}
```

## Grid

Grid uses familiar track strings. Place children explicitly when auto-placement is not enough.

```go
func Grid() {
	ui.View(
		ui.Display("grid"),
		ui.GridTemplateColumns("220px 1fr"),
		ui.Gap(16),
		func() {
			ui.Text("Sidebar")
			ui.Text("Content")
		},
	)
}
```

## Text and color

Typography inherits through the node tree. Colors accept hex, `rgb()`/`rgba()`, or packed RGBA values. Pass color and numeric accessors for reactive paint or size changes.

## Interaction states

`ui.Hover`, `ui.Active`, and `ui.Focus` describe interaction styles. `ui.When` applies options while a reactive condition is true and restores previous values when it turns false. Use `ui.DisabledStyle` and `ui.SelectedStyle` for those interaction states. Children remain mounted.

```go
func SelectableButton() {
	selected, setSelected := ui.CreateSignal(false)
	ui.Button(
		ui.BackgroundColor("#e5e7eb"),
		ui.When(selected, ui.BackgroundColor("#2563eb"), ui.Color("white")),
		ui.Hover(ui.Opacity(0.85)),
		ui.OnClick(func() { setSelected(!selected()) }),
		"Toggle selection",
	)
}
```

## Groups and named group hover

`ui.Group(true)` marks an unnamed hover group; `ui.Group("card")` names it. A descendant’s `ui.GroupHover(...)` follows its nearest ancestor group, including named groups. `ui.GroupHoverNamed("card", ...)` follows the nearest ancestor with that name, skipping intervening groups with other names.

```go
func GroupExample() {
	ui.View(ui.Group("card"), ui.Padding(20), func() {
		ui.Text(
			ui.Color("#64748b"),
			ui.GroupHover(ui.Color("#2563eb")),
			"Changes when the card is hovered",
		)
		ui.View(ui.Group("toolbar"), func() {
			ui.Text(
				ui.GroupHoverNamed("card", ui.Color("#2563eb")),
				ui.GroupHoverNamed("toolbar", ui.Opacity(0.8)),
				"Follows the card and the nested toolbar",
			)
		})
	})
}
```

Hovering any part of the group, including its padding and descendants, activates its rules. A nested group becomes the target for unnamed rules; named rules can still follow an outer group. With no matching ancestor, the rule has no effect. Repeated group rules accumulate in declaration order; a node’s own `ui.Hover(...)` wins for overlapping properties. Use paint properties such as colors, opacity, outlines, and transforms. Hover updates are handled natively without rerunning components or changing layout.
