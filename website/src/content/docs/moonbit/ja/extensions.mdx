拡張はコアを変更せずに任意のネイティブサービスを追加します。Go と MoonBit はマニフェストとサービス ABI を共有し、公開ラッパーは各フロントエンドが提供します。

## 拡張の種類を選ぶ

`moonbit`、`rust`、`zig`、`go` を指定できます。MoonBit テンプレートは Bun、MoonBit（v0.10.11 で検証）、ネイティブ C コンパイラで独立したサービスライブラリを作ります。Windows では MSVC 開発者シェルで `cl` または `clang-cl` と Windows SDK を使います。`MOON`、`MOON_HOME`、`CC` でツールを指定できます。プロバイダー自体には Go も QuickGUI SDK も不要です。同梱の Go ラッパーとデモは別のフロントエンドからの利用例です。

## 拡張プロジェクトを作成する

QuickGUI チェックアウトからプロバイダーを作成します。

```sh
bun packages/cli/src/cli.ts init-extension my-service --type moonbit --no-install
cd my-service
bun run build
moon -C native test --target native --release
```

## コンポーネントの共有

再利用できる MoonBit UI コンポーネントは `@ui.Element` を返す通常の関数です。MoonBit パッケージに置き、内容、コールバック、getter を引数で受け取ります。UI だけのコンポーネントにはサービスプロバイダーや新しいネイティブライブラリーは不要です。

```moonbit
pub fn notice(message : String) -> @ui.Element {
  @ui.text(message).padding(16).border_radius(8)
}
```

## ネイティブ拡張の構成

雛形は `native/` のプロバイダーソース、`artifacts/` のライブラリー、任意の Go ラッパーとデモを分離します。成果物ディレクトリーには `quickgui.extension.json`、対象ライブラリー、パッケージ情報を置きます。アプリのラッパーとプロバイダー実装を分けて管理します。

## 依存関係の宣言

```toml
[native]
extensions = ["vendor/my-service"]
```

ディレクトリのパスはアプリのプロジェクトからの相対パスです。CLI は各ディレクトリ内の `quickgui.extension.json` を読み取ります。このマニフェストはプロバイダー名、バージョン、対象の成果物を宣言します。対応する各ターゲットのライブラリをビルドしてください。CLI は明示的に選んだプロバイダーを検証・パッケージ化し、アプリ起動前に読み込みます。MoonBit は Go のインポートから拡張を検出しません。

### サービスを呼び出す

生成された `my-service` プロバイダーは MoonBit ラッパーから呼び出せます。

```moonbit
fn echo(message : String, done : (Result[Json, String]) -> Unit) -> Unit {
  @native.invoke("extension/my-service/echo", Json::string(message), done)
}
```

有効なコンポーネント、イベント、アプリの所有者内からラッパーを呼びます。返信は登録時の所有者のライフタイムに従います。継続的なセッションでは `window=0` で `extension-event` を購読し、`event.target` をセッションで絞り、後始末でセッションを閉じます。ネイティブのワーカースレッドは MoonBit を直接呼ぶのではなく、サービス ABI を通してリクエストを完了してください。

## ネイティブインターフェースを実装する

`native/extension.mbt` にサービス操作を実装します。

```moonbit
fn handle(
  _request : UInt,
  operation : Bytes,
  params : Bytes,
) -> Result[Bytes, String] {
  if operation == b"echo" {
    Ok(params)
  } else {
    Err("Unknown method")
  }
}
```

入力と成功時の返信は UTF-8 JSON バイト列、エラーは文字列です。元のバイト列を返すことで null と大きな整数を保持できます。アダプターは入力を MoonBit 所有のメモリへコピーし、64 KiB の制限を確認して返信し、ネイティブ sink を一度だけ解放します。回復可能な失敗には `Err` を返してください。`abort` はアプリを終了します。

生成されたアダプターはアプリの UI ワーカーで短い同期操作を処理します。非ブロッキングのゲートでランタイムへのアクセスを直列化し、処理と重なるメインスレッドからの終了要求はハンドラーが戻るまで保留します。同時または再入リクエストには busy エラーを返します。時間のかかるネイティブ処理や継続的セッションでは、C アダプターを拡張して入力をコピーし、完了まで sink を保持してください。バックグラウンドワーカーはネイティブの返信・イベントコールバックを使い、MoonBit 関数の呼び出し、借用リクエストコンテキストの保持、MoonBit オブジェクトへのアクセスを行わないでください。終了処理もブロックさせません。

バージョン付き登録、メソッドの分配、非同期完了、任意のセッションイベントを含む[拡張の契約](https://github.com/egoist/quickgui/blob/main/docs/architecture/extensions.md)を実装します。コアへの組み込みは不要です。

## 自動登録

CLI は明示的に選択したマニフェストを検証し、アプリ起動前にプロバイダーを読み込みます。コアは名前、バージョン、ABI、サービス表を検査し、名前に従って操作をルーティングします。MoonBit は Go のインポートからプロバイダーを検出しません。

## 成果物のビルドとパッケージ化

ビルドは MoonBit を C へコンパイルし、専用の非公開ランタイムを含む共有ライブラリをリンクします。公開するのはサービス記述子だけなので、MoonBit アプリや他のプロバイダーと共存できます。MoonBit の直接ネイティブバックエンドはまだ共有ライブラリのパッケージを生成できません。この方法も同一プロセスのネイティブ実行で、通常のアプリ編集では既存のライブラリを再利用します。

マニフェストが名前、リリースバージョン、成果物パッケージを管理します。`bun run build` でビルドし、プロバイダー編集後はデモを再起動します。`--module` は任意の Go ラッパーのモジュール名で、MoonBit 側は `native/moon.mod` で変更します。`moon -C native fmt` でフォーマットできます。生成された README に Go デモと公開前のローカル依存の手順があります。

## テストと配布

マニフェスト、ターゲットごとの成果物、サービスを公開する MoonBit パッケージを配布します。テンプレートは現在のホストのライブラリを `artifacts/lib/<platform>-<arch>/` へ配置します。対応するホストのビルドを集め、生成された MoonBit ライセンスと NOTICE を含む `artifacts/` を公開してください。利用側は `quickgui.toml` で拡張のディレクトリを選びます。ローカル開発では `QUICKGUI_EXTENSION_DIR` にそのターゲットディレクトリの絶対パスを指定します。実行ファイルを直接起動する場合は、さらに `run` の前に `@native.require_extension(name, version)` を宣言し、`QUICKGUI_LIBRARY` を指定します。

[Quick Git の I/O 拡張](https://github.com/egoist/quickgui/tree/main/examples/quick-git-moonbit/native)は非同期のプロセス・ファイルサービスの例です。TypeScript のランチャーが一度プロバイダーをビルドし、通常の MoonBit の編集では再利用します。
