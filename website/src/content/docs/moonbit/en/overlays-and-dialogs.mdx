Capture the current window while constructing a component. Its methods present OS dialogs and popup menus, with results delivered asynchronously.

## Popover

Create a trigger, positioner, and popup from `@ui.popover([])`. The native core handles placement, collisions, focus, and dismissal.

```moonbit
fn component_example() -> @ui.Element {
  let popover = @ui.popover([]).side("bottom").side_offset(6)
  popover.children([
    popover.slot(@ui.Trigger).label("Details"),
    popover
    .slot(@ui.Positioner)
    .children([
      popover
      .slot(@ui.Popup)
      .children([@ui.text("Popover content")])
      .padding(16),
    ]),
  ])
}
```

## Dialog

Create modal content from `@ui.dialog([])` and its Portal, Backdrop, Popup, Title, Description, and Close slots. The core keeps focus inside the modal and owns dismissal.

```moonbit
fn component_example() -> @ui.Element {
  let dialog = @ui.dialog([])
  dialog.children([
    dialog.slot(@ui.Trigger).label("Open dialog"),
    dialog
    .slot(@ui.Portal)
    .children([
      dialog.slot(@ui.Backdrop),
      dialog
      .slot(@ui.Popup)
      .padding(24)
      .flex_col()
      .gap(12)
      .children([
        dialog.slot(@ui.Title).label("Confirm action"),
        dialog.slot(@ui.Description).label("Review before continuing."),
        dialog.slot(@ui.Close).label("Close"),
      ]),
    ]),
  ])
}
```

## System popover

`@ui.system_popover([]).system_content(...)` creates content in a separate native child window. Provide its size and placement, and create its QuickGUI nodes inside the content callback.

```moonbit
fn component_example() -> @ui.Element {
  @ui.system_popover([])
  .label("Open details")
  .system_content(
    () => @ui.view([@ui.text("Native child window")]).padding(16),
    options={
      "width": 260,
      "height": 120,
      "popoverPlacement": "bottom-start",
      "popoverDismissOnEscape": true,
      "popoverDismissOnPointerOutside": true,
    },
  )
}
```

## Native dialogs

### Choose a directory

```moonbit
fn folder_picker() -> @ui.Element {
  let window = @native.current_window()
  let (selected, set_selected) = @ui.create_signal("No folder selected")
  @ui.view([
    @ui.button("Open folder").on_click(() => {
      window.dialog(
        1,
        { "title": "Open folder", "files": false, "directories": true },
        result => {
          match result {
            Ok([String(path), ..]) => set_selected(path)
            Ok(_) => ()
            Err(error) => set_selected(error)
          }
        },
      )
    }),
    @ui.text(selected()),
  ])
  .flex_col()
  .gap(12)
}
```

Dialog kind `0` is an alert, `1` opens paths, and `2` saves a path. Open/save results contain a paths array; an empty selection is cancellation. Alerts return the chosen button identifier. Handle the `Result` instead of blocking the UI thread.

### Popup and context menus

```moonbit
fn menu_button() -> @ui.Element {
  let window = @native.current_window()
  let (status, set_status) = @ui.create_signal("Ready")
  let open = () => {
    window.popup_menu([
      @native.menu_action("Refresh", () => set_status("Refreshed")),
      @native.MenuItem::Separator,
      @native.menu_action("Close window", () => window.close()),
    ])
  }
  @ui.view([
    @ui.button("Actions").on_click(open).on_context_menu(open),
    @ui.text(status()),
  ])
  .flex_col()
  .gap(8)
}
```

`popup_menu` keeps action callbacks alive until the menu dismisses. Use `submenu` for nested items and `menu_role` for standard platform commands. Event handlers and menu items retain the registering owner.

### Application menus and overlays

Call `@native.set_application_menu(items)` inside the application startup callback to install app-level menus. Use platform roles for commands such as closing, hiding, or minimizing a window.

Use [Dialog](/docs/moonbit/components/dialog), [Popover](/docs/moonbit/components/popover), [SystemPopover](/docs/moonbit/components/system-popover) and [Tooltip](/docs/moonbit/components/tooltip) for their native focus, dismissal and lifetime behavior. Components retain their parts and let the core handle transition completion. Model-driven `popover_menu([])` uses `.when_open(...)` to mount its popup only while open.
