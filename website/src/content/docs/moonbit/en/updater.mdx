Package the optional updater service for a MoonBit application.

## Configuration

Configure `[updates]` in `quickgui.toml` with your public key and download base URL. The TypeScript CLI creates appcast metadata and signed packages for both frontends.

## Application usage

MoonBit does not yet expose a dedicated updater-session helper. An application wrapper must manage the updater’s service ABI, session identity, `check` / `install` / `automatic` commands, and persistent `extension-event` subscriptions. The plain `@native.invoke` call does not return its request/session ID, so calling `start` alone is not a complete integration. See [Authoring Extensions](/docs/moonbit/extensions) for the service contract.

## Lifecycle

Keep the updater session at application scope so closing one window does not stop updates. Handle completion errors and state events on the UI thread. Send the session’s `stop` request on cleanup; provider shutdown releases its remaining resources. An accepted installer handoff can outlive the session.

## Platforms

macOS uses Sparkle with signed app archives. The portable backend supports Windows installers and Linux AppImages. Build and validate on each target host; shipping a backend does not establish runtime acceptance for every platform.

## Publishing

Use `quickgui keygen --sparkle` to create signing keys and keep the private key outside the repository. Build with `quickgui build`, then publish the generated appcast and signed release archive at the configured download location.

## Native artifacts

Select the updater extension directory under `[native].extensions`. The CLI reads `quickgui.extension.json` inside it and packages the provider; MoonBit does not inspect Go imports. macOS uses Sparkle, and the other platforms use the compatible native updater service. Service wrappers use the same extension ABI described in [Authoring Extensions](/docs/moonbit/extensions).
