A component is a function returning `@ui.Element`. Construct its nodes once, then bind the values that should change. The native core owns layout and rendering.

## View syntax

Constructors accept only children or content. Empty containers use `[]`; buttons also accept a string or one element. Apply styles, properties, and event handlers through fluent methods such as `.padding(24)`, `.checked(checked())`, and `.on_click(save)`. Use `.style(shared)` for reusable styles.

```moonbit
///|
fn settings_card() -> @ui.Element {
  @ui.div([
    @ui.text("Settings").style(@ui.style().font_size(20)),
    @ui.button("Save").on_click(() => println("Saved")),
  ])
  .style(@ui.style().padding(24).gap(12))
  .flex_col()
}
```

Read getters directly in fluent properties: `@ui.checkbox([]).checked(checked()).on_checked_change(set_checked)`. Literal properties initialize component-owned state; expressions containing signal reads become controlled bindings. Styles merge in declaration order. Use child lists throughout; scoped parts can attach a complete list with `.children([...])`.

## Live bindings

```moonbit
///|
fn greeting() -> @ui.Element {
  let (name, set_name) = @reactive.create_signal("World")
  @ui.div([
    @ui.input().value(name()).on_input(set_name),
    @ui.text("Hello, \{name()}!"),
  ])
  .flex_col()
  .gap(12)
}
```

`@reactive.create_signal(initial)` returns `(read, write)`. A call such as `@ui.text("Count: \{count()}")` is reactive when built with QuickGUI. The compiler also tracks expressions in button content, native properties, fluent styles, interaction styles, and child lists. Each binding updates its own retained nodes; the component does not rerun. Binding expressions must be pure.

Ordinary setup remains ordinary MoonBit: `let initial = count()` captures a snapshot. Event handlers run only on events. Use `@reactive.untrack(count)` for an untracked read. Custom components keep normal parameter types: pass a getter when their input should stay live. Explicit `bind_*` methods and the lower-level `Signal` handle remain available for manual composition and keyed rows.

## Derived state and cleanup

`@reactive.memo(() => expression)` returns a signal for a derived value. `@reactive.create_effect` tracks its actual reads, including conditional dependencies. `@reactive.batch` coalesces related writes. Avoid effects that rebuild an entire view to update one label.

Components and dynamic branches own their subscriptions. Register teardown with `@reactive.on_cleanup`. Removing the owner retires its effects and callbacks; new windows have independent owners.

## Conditional children

```moonbit
///|
fn disclosure() -> @ui.Element {
  let (expanded, set_expanded) = @reactive.create_signal(false)
  @ui.div(
    [
      @ui.button("Toggle details").on_click(() => set_expanded(!expanded())),
      ..if expanded() {
        [@ui.text("Details are mounted only while expanded.")]
      } else {
        [@ui.text("Collapsed")]
      },
    ],
  )
  .flex_col()
  .gap(8)
}
```

The branch factory runs when the predicate switches branches. Put values that change within that branch in bindings so its nodes can stay mounted.

## Keyed children

```moonbit
fn names_list() -> @ui.Element {
  let (names, _) = @reactive.create_signal(["Ada", "Grace", "Linus"])
  @ui.div([])
  .flex_col()
  .children_keyed(() => names(), name => name, row => @ui.text(row.get()))
}
```

Keys must be unique and stable. The render callback receives a row signal, so existing rows can update without replacing native node IDs or local state. Keyed children alone do not virtualize a long list; use [table visible ranges](/docs/moonbit/components#tables-and-visible-rows).

## Checking, testing, and debugging

Use `quickgui check` and `quickgui test` so tests receive the same view transform as builds. Add `--release` for release-backend tests. Raw `moon check` checks the original types, while raw `moon test` bypasses implicit view bindings.

The CLI preserves source files and maps compiler diagnostics, assertion failures, and symbolicated stack locations back to them. Native debugger breakpoints and stepping currently use the generated files in `.quickgui/moonbit-sources`; original-file breakpoint mapping is not supported yet. Editor completion and type checking continue to use ordinary MoonBit.
