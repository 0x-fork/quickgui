Call `@native.run` once. Its startup callback creates windows and registers application services. Results and events run on the MoonBit UI thread.

## Window lifetime

Use `@ui.window(component, options=...)` to create a window; each window owns an independent tree. `@native.current_window()` is valid while building a component or handling a window callback. Capture that handle for later `.close()` or `.focus()` calls.

Creation is asynchronous. Wait for `window-ready-to-show` before querying native geometry or state. Set `show: false` to prepare a hidden window. Options use the native JSON schema, including `title`, `width`, `height`, `background`, `titleBarStyle`, `trafficLightX`, and `trafficLightY`.

## Commands and services

`@native.command(json, callback)` sends platform commands. `@native.invoke(operation, params, callback)` calls an asynchronous native service. Both callbacks receive `Result[Json, String]`. Use them for operations that need a response. `@native.call` is restricted to the core’s synchronous CPU-only allowlist.

Callbacks belong to their registering owner. If an operation should survive the row or dialog that starts it, register it inside `window.with_owner(() => { ... })`. Closing that window still retires the callback.

## Events and file watching

`@native.on_event(kind, listener)` subscribes in the current window context. `@native.subscribe` also returns a cancellation function. Use `window=0` for application-level events. `@native.watch_files(paths, changed, ready)` uses OS file notifications and returns a stop function. These subscriptions are cleaned up with their owner.

Persistent extension events use `extension-event`; filter `event.target` to the session you opened. See [Authoring Extensions](/docs/moonbit/extensions).
