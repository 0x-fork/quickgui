Extensions add optional native services without changing the core. Go and MoonBit share the same manifest and service ABI; each frontend supplies its own public wrapper.

## Create a provider

From the QuickGUI checkout, scaffold a provider:

```sh
bun packages/cli/src/cli.ts init-extension my-service --type moonbit --no-install
cd my-service
bun run build
moon -C native test --target native --release
```

The command accepts `moonbit`, `rust`, `zig`, or `go`. The MoonBit template builds a standalone service library with Bun, MoonBit (tested with v0.10.11), and a native C compiler. On Windows use an MSVC developer shell with `cl` or `clang-cl` and the Windows SDK. Set `MOON`, `MOON_HOME`, or `CC` to select tools. The provider itself needs neither Go nor the QuickGUI SDK; the included Go wrapper and demo show how another frontend can use it.

Write service operations in `native/extension.mbt`:

```moonbit
fn handle(
  _request : UInt,
  operation : Bytes,
  params : Bytes,
) -> Result[Bytes, String] {
  if operation == b"echo" {
    Ok(params)
  } else {
    Err("Unknown method")
  }
}
```

Inputs and successful replies are UTF-8 JSON bytes; errors are strings. Echoing the original bytes preserves nulls and large numbers. The adapter copies inputs into MoonBit-owned memory, checks the 64 KiB payload limit, emits the reply, and releases its native sink exactly once. Expected failures should return `Err`; `abort` terminates the application.

The build compiles MoonBit to C, then links a shared library with its own private runtime. Only the service descriptor is exported, so the provider can coexist with a MoonBit app and other providers. MoonBit's direct native backend does not yet produce [shared-library packages](https://docs.moonbitlang.com/en/latest/language/ffi.html#export-functions); this build path stays native and runs in the same process. Ordinary application edits reuse the built artifact.

The generated adapter handles bounded synchronous operations on the application's UI worker. A nonblocking gate serializes runtime access, defers overlapping main-thread shutdown until the handler returns, and rejects concurrent or reentrant requests with a busy error. For slow native work or persistent sessions, extend the C adapter to copy input and retain the sink until completion. Workers must use the native reply/event callbacks and must not call MoonBit functions, retain the borrowed request context, or touch MoonBit-managed objects. Keep shutdown nonblocking.

The manifest supplies the provider name, release version, and artifact package. Build through `bun run build`, and restart the demo after provider edits. `--module` sets the optional Go wrapper's module; edit `native/moon.mod` for the MoonBit provider module. `moon -C native fmt` formats the provider. The generated README covers the Go demo and local dependencies before publication.

Implement the [extension contract](https://github.com/egoist/quickgui/blob/main/docs/architecture/extensions.md): versioned registration, method dispatch, asynchronous completion, and optional session events. No core integration is needed.

## Select and package

```toml
[native]
extensions = ["vendor/my-service"]
```

Directory paths are relative to the app project. The CLI reads `quickgui.extension.json` inside each directory; that manifest declares the provider name, version, and target artifacts. Build its library for each supported target. The CLI validates and packages explicitly selected providers and loads them before app startup. MoonBit does not discover extensions from Go imports.

## Invoke a service

For the generated `my-service` provider, a MoonBit wrapper can call:

```moonbit
fn echo(message : String, done : (Result[Json, String]) -> Unit) -> Unit {
  @native.invoke("extension/my-service/echo", Json::string(message), done)
}
```

Call the wrapper inside a live component, event, or application owner. Replies use the registering owner’s lifetime. For ongoing sessions, subscribe to `extension-event` with `window=0`, filter `event.target` to the session, and close the session on cleanup. Native worker threads must complete requests through the service ABI instead of calling MoonBit directly.

## Distribution and examples

Distribute a manifest, per-target native artifacts, and a MoonBit package exposing the service. The template stages the current host's library in `artifacts/lib/<platform>-<arch>/`; collect builds from each supported host and publish `artifacts/` with its generated MoonBit license and notice. Consumers select the extension directory in `quickgui.toml`. For local development set `QUICKGUI_EXTENSION_DIR` to that absolute target directory. For direct executable runs, also declare `@native.require_extension(name, version)` before `run` and provide `QUICKGUI_LIBRARY`.

[Quick Git’s I/O extension](https://github.com/egoist/quickgui/tree/main/examples/quick-git-moonbit/native) demonstrates asynchronous process/file services. Its TypeScript launcher builds the provider once and reuses it during ordinary MoonBit edits.
