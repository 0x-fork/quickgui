An extension is either a Go package of reusable components, or a Go package plus a native library for a service the app can call. Start with a Go package. Add a native library only when you need an optional backend, as the terminal and [updater](/docs/go/updater) packages do.

## Choose an extension type

| What you are adding | What you ship |
| --- | --- |
| Components or application logic | A Go module |
| A native service or optional backend | A Go package, a manifest, and a native library |
| UI backed by native data | A native service plus Go components |

Consumers import your Go package. The CLI finds the manifest and bundles the matching native artifact.

## Create an extension project

```sh
quickgui init-extension my-components --type go
quickgui init-extension my-service --type zig
quickgui init-extension my-service --type rust
```

`go` is the default and scaffolds a reusable component. `zig` and `rust` scaffold a native service with a typed Go wrapper, a manifest, and an npm artifact package. Every template includes `cmd/demo` and `quickgui.toml`:

```sh
cd my-service
bun run dev
```

Use `--module github.com/acme/my-service` for the Go module and `--npm-package @acme/extension-my-service` for the artifact package. Zig templates need Zig 0.16.x. From this checkout, run `bun packages/cli/src/cli.ts init-extension` until the CLI is published.

## Share a component

Export component functions from your own module. This package needs no native manifest.

```go
package notice

import "github.com/egoist/quickgui/go/ui"

func Notice(message func() string, styles ...ui.StyleBuilder) *ui.Element {
	return ui.Text(
		message(),
	).
		Padding(12).
		BackgroundColor("#eff6ff").
		TextColor("#1e40af").
		BorderRadius(8).
		Style(ui.Style().
			Merge(styles...))
}
```

Publish with Go version tags. Consumers add it with `go get`. Importing `terminal` or `updater` still opts an app into those native packages, so keep optional integrations in separate packages.

## Lay out a native extension

The [`native-extension` example](https://github.com/egoist/quickgui/tree/main/examples/native-extension) pairs a Go package with a small C library. It builds against [`quickgui_extension.h`](https://github.com/egoist/quickgui/blob/main/include/quickgui_extension.h).

```text
go.mod
echo/
  echo.go
  quickgui.extension.json
native/
  quickgui_extension.h
  echo.c
artifacts/
  package.json
  lib/darwin-arm64/libquickgui_acme_echo.dylib
build-extension.ts
```

C, C++, Rust, and other languages that export a C ABI can implement an extension. Rust extensions can vendor [`extension_api.rs`](https://github.com/egoist/quickgui/blob/main/src/extension_api.rs) and build a `cdylib` without linking QuickGUI itself.

## Declare dependencies

Place this manifest **beside the imported Go package’s source**:

```json
{
  "schema": 1,
  "name": "acme-echo",
  "abi": 1,
  "package": "@acme/extension-echo",
  "version": "1.0.0",
  "library": "quickgui_acme_echo"
}
```

Names start with a lowercase letter and contain at most 64 lowercase letters, digits, or hyphens. `host` is reserved. The library field is `quickgui_` plus the name with hyphens replaced by underscores.

The Go package records the requirement and exposes a typed call:

```go
package echo

import (
	"encoding/json"

	"github.com/egoist/quickgui/go/host"
	"github.com/egoist/quickgui/go/native"
)

func init() {
	host.RequireExtension("acme-echo", "1.0.0")
}

func Send(message string, done func(string, error)) {
	native.InvokeExtension("acme-echo", "echo", message, func(raw string, err error) {
		var reply string
		if err == nil {
			err = json.Unmarshal([]byte(raw), &reply)
		}
		done(reply, err)
	})
}
```

Call operations after `native.Run` is ready. For a persistent service, `native.OpenExtension(name, options, changed, ready)` returns a session. Close it on the UI goroutine when the owner is disposed.

The CLI discovers manifests through `go list -deps`. Both the manifest and `RequireExtension` are required: one controls bundling, the other controls loading.

## Implement the native contract

Export `quickgui_extension_v1` with C linkage. It returns a descriptor with your name, version, ABI version `1`, and a two-function table (`invoke` and `shutdown`). Copy borrowed request bytes before keeping them, return quickly, and reply later.

| Request | What the extension does |
| --- | --- |
| A one-shot method such as `echo` | Reply once |
| `start` | Open a session and keep its event sink |
| A command such as `send` | Find that session and reply to this command |
| `stop` | Cancel that session |
| `shutdown` | Cancel every session without blocking |

Request and reply payloads are each limited to 64 KiB. The [C echo implementation](https://github.com/egoist/quickgui/blob/main/examples/native-extension/backend/echo.c) is a complete one-shot example.

## Automatic registration

The app loads each selected library at startup and checks its name, version, and ABI. Conflicting versions of the same name fail. Images stay loaded for the process lifetime; your shutdown function must cancel remaining sessions.

## Build and package artifacts

Build the native library for each host you support and stage it under `artifacts/lib/<platform>-<arch>/`. Publish that folder as an npm package whose `version` matches the manifest.

```json
{
  "name": "@acme/extension-echo",
  "version": "1.0.0",
  "files": ["lib", "README.md"],
  "exports": { "./package.json": "./package.json" }
}
```

Helper files go next to the library. Declare their basenames in a manifest `resources` object keyed by `darwin`, `linux`, or `windows`.

## Test and distribute

Consumers `go get` your module and run `quickgui dev`. The CLI fetches the matching npm package, or you can set `QUICKGUI_EXTENSION_DIR` to a local artifact directory while developing.

Confirm that an app without the import does not bundle the extension, that adding the import includes it, and that closing sessions stops events. End users receive the packaged app; they do not need Bun or a native toolchain to run it.
