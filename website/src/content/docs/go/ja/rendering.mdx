コンポーネントはマウント時に保持ツリーを作成します。リアクティブなバインディングが対象ノードを更新し、レイアウト、描画、アクセシビリティはネイティブコアが担当します。

## レンダリングモデル

すべてのコンポーネントと UI 構築コールバックは `*ui.Element` または `*native.Node` を返します。子ノードを直接渡し、複数の兄弟には `ui.Fragment(...)` を返します。UI 構築結果の破棄と戻り値のない宣言ブロックはコンパイルエラーになります。イベントやエフェクトのコールバックは従来のシグネチャです。

```go
func ViewExample() *ui.Element {
	return ui.View().Children(

		ui.Text("Hello from Go"),
		ui.Button().Child("Continue").OnClick(func() {}),
	).Padding(20).Gap(12)
}
```

## 条件付きコンテンツ

状態に応じて子をマウントまたは削除するには `ui.Show` を使います。通常の Go の `if` は構築時だけ実行されます。同じ分岐が選ばれている間はノードを保持し、分岐を削除するとバインディングも破棄します。

```go
func DisclosureExample() *ui.Element {
	open, setOpen := ui.CreateSignal(false)
	return ui.View().Children(
		ui.Button().Child("Toggle details").OnClick(func() { setOpen(!open()) }),
		ui.Show(
			open,
			func() *ui.Element { return ui.Text("Details") },
		),
	)
}
```

## リストとノードの同一性

`ui.For` でリアクティブなリストを作り、一意で安定したキーを渡します。保持された行が変更されるデータを読むには `ui.KeyedFor` の項目アクセサーを使います。削除した行は購読を解除し、キー付きの行の移動はネイティブノードの同一性を保ちます。仮想化されたテーブルやリストは、大きな集合でも可視行だけをマウントします。

キーには位置ではなく、データベースの ID などの安定した識別子を使います。この例では既存の行を並べ替え、行アクセサーを通して ID 1 のラベルを更新します。親はリストを作り直しません。データを変更するときは新しいスライスを渡してください。保存済みのスライスを直接書き換えても購読側に通知されません。

```go
type ListPerson struct {
	ID   int
	Name string
}

func KeyedListExample() *ui.Element {
	people, setPeople := ui.CreateSignal([]ListPerson{{1, "Ada"}, {2, "Grace"}})
	return ui.View().Children(
		ui.Button().Child("Reorder and rename").OnClick(func() {
			setPeople([]ListPerson{{2, "Grace"}, {1, "Ada Lovelace"}})
		}),

		ui.KeyedFor(
			people,
			func(person ListPerson) any { return person.ID },
			func(person func() ListPerson, index func() int) *ui.Element {
				return ui.Text(
					index(),
					": ",
					person().Name,
				)
			},
			func() *ui.Element { return ui.Text("No people") },
		),
	)
}
```

## ウィンドウのライフサイクル

`WindowOptions.Component` はウィンドウごとにリアクティブルートを作成します。閉じるとノードとエフェクトが破棄されます。リソースの後始末は `ui.OnCleanup` に登録します。バックグラウンド処理には `ui.Async` を使うと、結果が UI goroutine に返され、コンポーネント破棄時にキャンセルされます。

バックグラウンド処理はコンポーネントのマウント時に開始します。`load` は UI goroutine の外で動き、コンテキストのキャンセルに従う必要があります。完了コールバックでは安全にシグナルを書き込めます。所有する分岐の削除やウィンドウの終了時にはコンテキストがキャンセルされ、遅れて届いた完了通知も破棄されます。この例では標準の `context` パッケージを使います。

```go
func LoadingPanel(load func(context.Context) (string, error)) *ui.Element {
	result, setResult := ui.CreateSignal("Loading…")
	ui.Async(
		load,
		func(value string, err error) {
			if err != nil {
				setResult(err.Error())
				return
			}
			setResult(value)
		},
	)
	return ui.Text(result())
}
```

## 現在のウィンドウ

コンポーネントのマウント時に `native.CurrentWindow()` を取得し、コールバックではそのウィンドウを使います。無関係な goroutine から取得しないでください。ウィンドウイベントやネイティブリクエストは非同期コールバックで結果を返します。

```go
func CloseButton() *ui.Element {
	window := native.CurrentWindow()
	return ui.Button().Child("Close window").OnClick(func() { window.Close() })
}
```

## チェック・テスト・デバッグ

アプリのモジュールで `quickgui test` を実行し、開発ビルドと同じビューコンパイラーを使います。`quickgui fmt --check` で書式を確認します。アプリはネイティブ Go 実行ファイルなので、通常の Go 診断やデバッガーは元のソースを使用します。
