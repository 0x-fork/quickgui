# Performance guide

## Performance invariants

Read [rendering architecture](rendering.md) and [optimization coverage](rendering-optimization-plan.md) before changing invalidation, layout, painting, runtime scopes, native-host mutations, or GPU resource reuse. Preserve these contracts:

- Keep the runtime asleep while clean. Equivalent mutations must remain no-ops without advancing revisions or requesting redraws. Batch mutations and coalesce redraw requests and wheel work at frame boundaries; do not introduce unconditional polling, declarations, or redraws.
- Invalidate the smallest correct phase and subtree. Color and opacity changes need paint, not intrinsic layout. Text, font metrics, constraints, and scale changes must invalidate affected measurement and dependent geometry. Transforms update placement, hit testing, paint, and accessibility geometry without intrinsic layout. Keep selection and accessible content current even when declaration or layout is skipped.
- Preserve stable element identities, retained Taffy nodes, text measurement/shaping caches, and keyed focus, selection, scroll, and input state. Reconcile changed styles, measurement inputs, and child edges rather than clearing the layout arena. A clean layout root with unchanged viewport and scale must skip layout.
- Route ordinary Go-host property mutations through retained updates and structural/layout/listener mutations through supported scopes. Rust dependencies should use component restart scopes or direct value bindings where appropriate. Do not turn a local mutation into root `View::render`, whole-tree reconciliation, or a global cache reset without demonstrating why it is required.
- Keep dependency and callback ownership scoped. Dirty parents subsume descendant restarts; unmount removes listeners, subscriptions, dependency edges, and retained resources. Retired indexed listener keys must never alias new callbacks. For keyed moves, invalidate both parents, detach changed edges before reattaching, and retire all affected scopes before declaring replacements. Validate mutation batches before applying them so rejection cannot leave partial state.
- Preserve conservative declaration fallbacks for unsupported scopes, compound native parts, hoisted portals, callback-owned declarations, and asynchronous resources. Broaden a fast path only when it handles the same dependencies and lifecycle cleanup. Do not skip necessary work merely to improve a counter.
- Reuse immutable subtree drawing-command chunks without copying or flattening the entire display list. Invalidate dirty ancestor paths and affected descendants for inherited styles, named groups, focus, selection, and scrolling. Cache reuse must account for clips, transforms, stacking order, scale, and native-view placement. Dynamic callbacks and effects need explicit dependency handling before they can be cached.
- Use the same content-box and text geometry for measurement, shaping, painting, selection, and hit testing. Commit virtual-list geometry after layout and before paint. Keep mounted virtual rows proportional to the viewport plus bounded overscan; avoid full-list construction on scroll or hover.
- Keep native font rasterization on glyph-atlas misses and its caches bounded. Optical size uses logical font size; DPI changes raster resolution. Preserve native smoothing keys and encoded-sRGB UI blending across every primitive and retained group. Changing only text gamma or switching back to an sRGB render attachment can make small labels too thin again; validate actual pixels and opacity together.
- Bound caches and upload shadows by explicit entry/byte limits, allocate them lazily, and evict or release stale resources. Preserve bounded text caches and stable text identities. Do not trade reduced CPU work for unbounded retained memory.
- GPU upload reuse must track each physical rotating buffer and reset its shadow after reallocation; preserve write alignment and bounded write counts. Compositing reuse must account for content, nested effects, scale, and physical texture generations, including pooled texture repurposing. Pointer identity alone is insufficient. Base and overlay work encoded before one submission must not overwrite each other's uniforms. Do not assume swapchain pixels survive presentation.

Optional native backends follow the [extension contract](extensions.md): keep one renderer/runtime in the core, transfer bounded immutable frames only when revisions change, release session workers on unmount, and reuse prebuilt artifacts during Go edits.

## Performance validation

TypeScript follows the same retained-mutation contract. Detached Solid JSX remains local until mounted; keyed moves preserve native IDs, and removed branches release their native nodes and listener routing. Each window owns an independent Solid root. Bun's worker receives copied native events through a bounded Rust queue and a coalesced notification, never a polling timer or cross-thread borrowed pointer. Property writes coalesce into a microtask batch and equivalent values do not submit work. Keep the client Solid runtime selected in both compiled applications and tests. Run `bun run test:typescript` and regenerate/check `scripts/generate-typescript.ts` when changing this boundary.

- For rendering or invalidation changes, add or update meaningful correctness and work regressions. Compare incremental layout or cached pixels against fresh results, and assert that unrelated branches avoid declaration, reconciliation, measurement, geometry, or paint work as appropriate. Preserve the hover regression where work and allocations remain independent of unrelated panel size. Do not weaken these checks to accommodate a regression.
- Use `FrameMetrics.pipeline`, `RenderStats`, and the test-only allocation probe to substantiate optimization claims. Report the measured phase and workload. CPU timings are not GPU timings; primitive upload counters exclude some texture/uniform traffic; UI-tree allocation checks are not complete frame benchmarks. Structural mount-index scans and renderer preparation can still process the full tree or scene.
- Start with relevant regressions in `src/ui_tree/tests/layout_invalidation.rs`, `src/runtime/test_context/tests/scopes.rs`, `crates/quickgui-host/src/tests/incremental.rs`, and `src/renderer/tests.rs`. Cover inherited state, reparenting/unmount, and buffer/texture reuse when the affected fast path depends on them. See the coverage document for additional tests.
- For substantial rendering changes, run `cargo test --lib` and `cargo test -p quickgui-host --lib`; on macOS, prefix each with `scripts/with-macos-ghostty-zig.sh`. Run `bash scripts/check-go.sh` with Go on `PATH` when changing Go APIs or their integration. Check Rust formatting with `cargo fmt --all -- --check` and whitespace with `git diff --check`. Documentation-only changes need diff checks, not native builds.
- Rebuild and stage the native library with `bun packages/native/build.ts` before claiming an example uses native changes. Respect existing dev watchers and distinguish source/headless verification from live interaction and visual testing.
